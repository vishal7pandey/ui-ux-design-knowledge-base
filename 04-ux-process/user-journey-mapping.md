# User Journey Mapping

A user journey map is a visual story of a user’s experience over time. It helps teams see the whole experience, find pain points, and identify opportunities.

---

## 1. What Is a Journey Map?

A journey map shows:

- The user’s goal.
- The steps they take.
- What they think, feel, and do at each step.
- The touchpoints with the product or service.
- The pain points and opportunities.

---

## 2. Parts of a Journey Map

| Section | Description |
|--------|-------------|
| **Persona** | Who the user is. |
| **Scenario** | What they are trying to achieve. |
| **Phases** | High-level stages of the journey. |
| **Actions** | What the user does. |
| **Thoughts** | What the user thinks. |
| **Emotions** | How the user feels. |
| **Touchpoints** | Where the user interacts with the product. |
| **Pain points** | Frustrations and problems. |
| **Opportunities** | Ideas for improvement. |

---

## 3. Common Phases

A typical journey has five phases:

1. **Awareness**: the user learns about the product or need.
2. **Consideration**: the user evaluates options.
3. **Onboarding**: the user starts using the product.
4. **Usage**: the user gets value from the product.
5. **Advocacy or churn**: the user renews, expands, or leaves.

For an in-product task, phases might be:

1. **Goal**: the user decides to do something.
2. **Discover**: the user finds how to start.
3. **Act**: the user performs the task.
4. **Resolve**: the task is complete.
5. **Reflect**: the user evaluates the experience.

---

## 4. How to Build a Journey Map

1. **Pick a persona and scenario.**
2. **Identify the phases.**
3. **Map the user’s actions, thoughts, and feelings.**
4. **List touchpoints with the product, service, or people.**
5. **Find pain points and opportunities.**
6. **Prioritize and assign owners.**

---

## 5. When to Use Journey Maps

- At the start of a project to understand the problem.
- When onboarding new team members.
- When a feature or flow has low completion or satisfaction.
- When the team disagrees on what the user experience is.

---

## 6. Journey Mapping Best Practices

- Base the map on research, not assumptions.
- Focus on one persona and one scenario per map.
- Include emotions, not just actions.
- Make it visual and easy to share.
- Use it to find opportunities, not just document the current state.
- Update as you learn more.

---

## 7. Common Mistakes

- Mapping the ideal journey instead of the real one.
- Including too many personas or scenarios.
- Ignoring emotions and thoughts.
- Creating the map and not using it.
- Making it too detailed to be useful.
- Not involving the team in the process.

---

## 8. Tools

- Miro, FigJam, Mural.
- Figma for high-fidelity maps.
- Whiteboards for workshops.
- Spreadsheets for data-heavy journeys.

---

## 9. Checklist

- [ ] Persona and scenario are clear.
- [ ] Phases match the user’s actual journey.
- [ ] Actions, thoughts, and emotions are included.
- [ ] Touchpoints are identified.
- [ ] Pain points are honest and research-based.
- [ ] Opportunities are prioritized.
- [ ] The map is visual and shareable.
- [ ] The team uses it to make decisions.
- [ ] Map is updated as the product evolves.
