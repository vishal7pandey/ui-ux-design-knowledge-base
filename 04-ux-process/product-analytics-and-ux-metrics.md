# Product Analytics and UX Metrics

Metrics help teams understand whether a product is working. UX metrics focus on how users experience the product, not just how it performs.

---

## 1. Categories of UX Metrics

| Category | Example metrics |
|----------|-----------------|
| **Task success** | Completion rate, error rate, time on task. |
| **Engagement** | Active users, session frequency, feature adoption. |
| **Satisfaction** | CSAT, NPS, SUS, UMUX. |
| **Retention** | Day 1/7/30 retention, churn. |
| **Efficiency** | Time to complete, clicks to goal, task success per session. |
| **Business** | Conversion, revenue, support tickets, cost per acquisition. |

---

## 2. HEART Framework

The HEART framework is a popular way to think about UX metrics.

| Letter | Meaning | Question |
|--------|---------|----------|
| **H** | Happiness | Do users like the product? |
| **E** | Engagement | Are users actively using it? |
| **A** | Adoption | Are new users trying the product? |
| **R** | Retention | Do users come back? |
| **T** | Task success | Can users complete their goals? |

---

## 3. Metrics by Stage

### Discovery

- Number of users interviewed.
- Themes identified.
- Assumptions tested.

### Design

- Prototype test pass rate.
- Number of design iterations.
- Usability issues found and fixed.

### Build

- Time to design.
- Time to handoff.
- Design-to-code fidelity.

### Launch

- Feature adoption.
- Task success rate.
- Error rate.
- Support tickets.

### Iterate

- Retention and churn.
- NPS or CSAT.
- Conversion impact.

---

## 4. Choosing Metrics

A good metric is:

- **Understandable**: the team knows what it means.
- **Actionable**: the metric can guide decisions.
- **Measurable**: it can be tracked consistently.
- **Relevant**: it ties to user or business goals.
- **Timely**: it is available when needed.

---

## 5. Common UX Metrics

| Metric | What it measures |
|--------|------------------|
| **Task success rate** | % of users who complete a task. |
| **Time on task** | How long it takes. |
| **Error rate** | How often users make errors. |
| **SUS (System Usability Scale)** | Overall usability. |
| **NPS (Net Promoter Score)** | Likelihood to recommend. |
| **CSAT (Customer Satisfaction)** | Satisfaction with a specific interaction. |
| **CES (Customer Effort Score)** | How easy a task was. |
| **UMUX** | Usability metric for user experience. |
| **Feature adoption** | % of users who use a new feature. |
| **Activation rate** | % of users who reach a key milestone. |

---

## 6. Setting Goals

- Use the **SMART** framework: Specific, Measurable, Achievable, Relevant, Time-bound.
- Define a baseline before making changes.
- Set a target and a timeline.
- Track progress and iterate.

---

## 7. Analytics and Qualitative Data

- Quantitative data tells you what is happening.
- Qualitative data tells you why.
- Combine analytics, surveys, interviews, and usability tests.
- Do not rely on numbers alone.

---

## 8. Common Mistakes

- Measuring vanity metrics like page views or downloads.
- Tracking too many metrics.
- No clear connection between metrics and goals.
- Not acting on the data.
- Not sharing metrics with the team.
- Confusing correlation with causation.
- Not tracking the same metric over time.

---

## 9. Checklist

- [ ] Metrics are tied to user or business goals.
- [ ] HEART or a similar framework is used.
- [ ] Baseline and targets are set.
- [ ] Metrics are understandable to the whole team.
- [ ] Qualitative and quantitative data are combined.
- [ ] Metrics are reviewed regularly.
- [ ] Action is taken based on findings.
- [ ] Metrics are shared transparently.
- [ ] Avoid vanity and overload.
- [ ] Metrics are tracked over time.
