# AI Output Editing and Refinement

AI output is rarely final. Users need easy ways to edit, refine, and adapt it. Good refinement UX turns generated content into useful content.

---

## 1. Why Output Refinement Matters

- AI output is a starting point, not a final product.
- Users need to add their voice, judgment, and context.
- Refinement is where trust and value are built.
- Easy editing reduces friction and increases adoption.

---

## 2. Editing Patterns

### Inline editing

- Click or tap to edit text directly.
- Highlight and change like a normal document.
- Best for documents, emails, and descriptions.

### Structured editing

- Edit specific fields in a form.
- Good for structured output like tables, code, or data.

### Diff view

- Show before and after side by side.
- Highlight changes.
- Good for reviewing AI edits to existing content.

### Suggestion mode

- AI proposed changes are shown as tracked changes.
- User accepts or rejects each one.
- Good for rewriting and reviews.

### Version history

- Save each version of the output.
- Let users compare and revert.
- Useful for long or important content.

---

## 3. Refinement Commands

- **Make it shorter**.
- **Make it longer**.
- **Change the tone** (more formal, friendlier).
- **Rewrite for [audience]**.
- **Add examples**.
- **Simplify**.
- **Add more detail**.
- **Fix grammar**.
- **Translate to [language]**.
- **Convert to [format]**.

---

## 4. UI for Refinement

### Refine bar

- A toolbar above or below the output with common commands.
- One-tap actions.
- Optional custom prompt field.

### Inline chips

- Small chips next to selected text: “Shorten,” “Rewrite,” “Explain.”
- Contextual to the selection.

### Follow-up prompt

- A text field where users can type how they want the output changed.
- “Make this more concise and action-oriented.”

### Tone and format selectors

- Dropdowns for tone, length, and format.
- Apply to the whole output or a selection.

---

## 5. Best Practices

- Make output editable by default.
- Show refinement options in context.
- Preserve the original while showing the new version.
- Let users undo any change.
- Support keyboard and mouse editing.
- Keep the interface fast and responsive.
- Let users accept or reject specific parts.
- Combine manual and AI-driven refinement.

---

## 6. Version and Compare

- Save original and refined versions.
- Allow side-by-side comparison.
- Highlight what changed.
- Let users revert or merge.

---

## 7. Accessibility

- Editable output is keyboard accessible.
- Controls have labels.
- Changes are announced to screen readers.
- Color is not the only cue for selected or changed content.

---

## 8. Common Mistakes

- Output that cannot be edited.
- Refinement options hidden or hard to find.
- AI overwrites without showing changes.
- No way to undo or revert.
- Too many refinement options at once.
- Refinement that ignores user intent.
- Output that is not scrollable or selectable.

---

## 9. Checklist

- [ ] Generated output is editable.
- [ ] Refinement options are visible and in context.
- [ ] Common commands are one tap away.
- [ ] Users can enter custom refinement instructions.
- [ ] Original and refined versions are saved.
- [ ] Changes are shown with highlights or diff.
- [ ] Undo and revert are available.
- [ ] Output works with keyboard and assistive tech.
- [ ] Refinement is fast and responsive.
- [ ] Users can accept or reject parts of the output.
