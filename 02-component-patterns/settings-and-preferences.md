# Settings and Preferences

Settings and preferences screens let users control the product. Done well, they feel organized and easy to scan. Done poorly, they become a dumping ground for every option.

---

## 1. Settings Design Principles

- **Group by theme.** Put related settings together.
- **Prioritize the most common ones.** Do not bury important options.
- **Use plain language.** Avoid internal jargon.
- **Provide sensible defaults.** Most users will not change settings.
- **Explain the impact.** Users should know what a setting does.

---

## 2. Common Categories

| Category | Examples |
|----------|----------|
| **Account** | Profile, email, password, security. |
| **Notifications** | Email, push, in-app, frequency. |
| **Privacy** | Data, permissions, sharing, visibility. |
| **Appearance** | Theme, font size, density, language. |
| **Accessibility** | Motion, contrast, text size, screen reader. |
| **Integrations** | Connected apps, imports, exports. |
| **Billing** | Plan, payment, invoices, seats. |

---

## 3. Layout

### Single page

- Good for simple products with few settings.
- Group with headings and dividers.
- Use sticky navigation for long pages.

### Tabbed sections

- Good for many categories.
- Keep tabs visible and scannable.

### Sidebar navigation

- Good for complex settings.
- Allows many categories and sub-pages.

---

## 4. Controls

| Control | Use for |
|---------|---------|
| **Toggle switch** | Binary on/off settings that take effect immediately. |
| **Checkbox** | Multiple independent, binary options. |
| **Radio button** | Mutually exclusive options. |
| **Dropdown** | Single selection from many options. |
| **Slider** | Numeric values within a range. |
| **Text input** | Custom values, names, URLs. |

---

## 5. Best Practices

- Place the most important settings first.
- Group related settings visually.
- Use clear, action-oriented labels.
- Show the current value clearly.
- Apply changes immediately or provide a save action.
- Confirm destructive actions.
- Provide a way to reset to defaults.
- Use search for large settings pages.

---

## 6. Saving and Feedback

### Auto-save

- Apply small changes immediately.
- Show a brief success indicator.
- Best for toggles, radios, and sliders.

### Manual save

- Use for important or complex changes.
- Show a clear save button.
- Confirm before leaving unsaved changes.

---

## 7. Mobile Settings

- Use a single scrolling list with grouped sections.
- Use drill-down pages for sub-categories.
- Keep labels and tap targets large.
- Place account, notifications, and appearance near the top.

---

## 8. Common Mistakes

- Dumping every option in one list.
- Using unclear labels or jargon.
- No grouping or hierarchy.
- Missing defaults or reset options.
- Requiring too many taps to change common settings.
- Not showing the current value.
- Hidden auto-save behavior.

---

## 9. Checklist

- [ ] Settings are grouped by category and theme.
- [ ] Most common settings are easy to find.
- [ ] Labels are plain and descriptive.
- [ ] Defaults are sensible and documented.
- [ ] Controls match the setting type.
- [ ] Changes are auto-saved or have a clear save action.
- [ ] Destructive actions are confirmed.
- [ ] Users can reset to defaults.
- [ ] Search is available for large settings pages.
- [ ] Mobile settings are thumb-friendly and scannable.
- [ ] Feedback is shown for important changes.
